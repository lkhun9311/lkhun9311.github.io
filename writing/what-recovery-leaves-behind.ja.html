Instance HA ⑧: 復旧が成功しても終わりではありませんでした
移すのに成功したあとも資源の割り当てとサービスの状態が残ります。片付けないと次の復旧が失敗します。

⑦編でどこへ送るかを決めました。 送って Instance が立ち上がり、画面には復旧完了と出ました。

ところが次の復旧が失敗しました。送る場所がないという理由でしたが、ノードには空きが ありました。

最初は容量の計算が違うのだと思いました。違いました。先の復旧が、去った場所に 資源の割り当てを残していました。

この記事の想定読者#

  • 自動復旧を入れて二回目からおかしくなった経験のある方
  • 復旧成功のあとの復元手順をまとめる必要がある方
  • 共有ストレージの上でノードごとの状態を扱っている方
  • ⑦編を読んで、送ったあとに何が残るのか気になる方

移せば終わりだと思っていました#

復旧の成功は Instance が別のノードで立ち上がったという意味です。その判定は正しいです。 ただその時点が片付けの終わった時点ではありません。

横にスクロールすると残りが見えます

復旧が成功したあとに残るもの。
残るもの症状いつ現れるか
去った場所の資源の割り当て同じ Instance が二か所で押さえられ資源が二度数えられる次の復旧が場所なしで失敗するとき
障害ノードの Compute サービス切れたままで復旧の対象になれないノードを戻したあとも空のとき
共有された状態ファイル先に起動したノードの値で上書きされるノードを再起動してサービスが上がらないとき
止まった Agent長く切れていると自分では戻らないノードは生きているのに障害に見えるとき

四つが違う層にあります。資源の集計とサービスの状態とファイルとプロセスなので 一度には片付かず、確認する場所も違います。

バージョン一つで結果が変わることもあります。Nova API を 2.95 以上に指定して evacuate を 呼ぶと、Instance は別のホストで立ち上がりますが停止した状態で移ります。画面は 移したと言い、実際に移りもしますが、サービスは動いていません。運用スクリプトがバージョンを 2.94 以下に固定しているのはそのためです。

去った場所に割り当てが残ります#

一番長くかかったのが一行目です。Instance は新しいノードで動いているのに、去ったノードの側にも その Instance の資源の割り当てが残っていました。

片付け自体は自動で回る経路が元からあります。ところがノードがネットワークの再接続で戻る場合には その経路が回りません。そこでノードが戻るときに去った側の割り当てだけを選んで消す片付けを 別に入れました。

ここで気をつけることが一つあります。いま実際に動いている側の割り当てまで消してはいけません。 だから別のノードで動いているのに復帰ノードの割り当てが残っているものだけを対象にします。

共有された状態ファイルが上書きされます#

二番目に長くかかったのは、ノードを戻したのにサービスが上がらなかったことです。ログはこのノードの 識別子が自分のものではないと言っていました。

原因は共有ストレージでした。複数のノードが同じディレクトリを分け合っていて、その中に ノードごとに違うべき状態ファイルが一つしかありませんでした。ノードを起動する順番に よって、先に上がった側の値で上書きされます。

直した方法は、そのファイルを共有パスから外してノードごとに自分の値を使わせることです。共有して よいものと共有してはいけないものが、一つのディレクトリにあったわけです。

二つの失敗は同じ根でした#

復旧が失敗したときに出たメッセージは二つでした。一つは共有ストレージ上の状態が正しくないという もので、もう一つは送る場所がないというものです。

横にスクロールすると残りが見えます

二つの失敗の原因と解決。
失敗実際の原因解決
共有ストレージ上の状態が正しくないという失敗設定値ではなく、先の失敗が残した割り当て残った割り当てを片付けてから再試行
送る場所がないという失敗同じ根。片付いていない割り当てが容量を使っている割り当てを片付けて資源の集計を更新

どちらも表面の言葉と実際の原因が違いました。先の失敗が残した割り当てが 二つの共通の根でした。設定値を変えて再試行しているあいだは見えません。

元に戻すのは自動ではありません#

最後は復元です。復旧は障害ノードの Compute サービスを切ります。もう一度スケジューリングされない ようにするためで正しい動作ですが、ノードを戻してもそのサービスは切れたままです。

# 画面が復旧完了と言ったあとに確認すること

  1. compute サービスの状態
     切れていたら入れ直す。復旧が切っており、自分では入らない

  2. ノードごとの状態値
     共有パスではなくノード自身のものを使っているか見る

  3. Agent の状態
     長く切れていたなら起動し直す

  4. 去った場所の資源の割り当て
     同じ Instance が二か所で押さえられていないか見る

横にスクロールすると残りが見えます

元に戻すときに確認すること。
確認なぜ
Compute サービスを入れ直したか復旧が切っており、自動では入りません
ノードごとの状態値が自分のものか共有ファイルを使うと他のノードの値で上書きされます
Agent が戻ったか長く切れていたなら起動し直す必要があります
去った場所の割り当ては空か残っていると次の復旧が失敗します

四行を順番に置きました。サービスを入れる前に状態ファイルを直す必要があり、 割り当ては最後に見てこそ前の三つが作った変化が反映されます。

おわりに#

この編の結論は一行です。復旧が成功したという判定と、片付けが終わった時点は別です。 そのあいだを空けておくと、次の復旧が代わりに失敗します。

そして残るものは画面に出ません。成功だけが見え、残りは次に別の顔で戻ってきます。だから復元を 手順として書いておくほうがよいのです。
