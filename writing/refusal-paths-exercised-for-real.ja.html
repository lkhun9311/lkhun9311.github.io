GPU 実験 Harness の拒否経路を実物で動かしてみました

実験の道具が出す数字は、条件が一つ付くときにだけ価値があります。クラスタが始まるときに綺麗で、 終わるときにも綺麗だったと証明できることです。

この Harness はその証明ができていませんでした。プレビューでない実行はすべて拒否されていて、 理由は有効性ゲートが未実装だということでした。片付けのほうには手をかけてあったのに、そこは ボトルネックではありませんでした。

最初、私は観測の連続性ゲートがかなり作ってあると見ていました。ファイルがありテストもあったから です。その判断が間違っていたことは前の記事に 書きました。この記事はそのあとにゲートを四つ立て、拒否経路を一つずつ実物で発火させた 記録です。

この記事の想定読者#

  • 実験やベンチマークの道具を自分で作って使っている方
  • ガードを入れたが、そのガードが実際に何を捕まえるのか確かめたい方
  • 測定値がシステムの性質なのか道具の誤差なのかを分けたい方
  • クラスタを使う実験で実行と実行のあいだに境界を立てたい方

数字はあるのに証拠がありませんでした#

ゲートは四つです。観測が途切れていないか、始まるときに環境が資格を備えているか、その資格が 実行のあいだ保たれたか、そしてその証拠がレコードに残ったかです。

観測の連続性を直したあと、歪みの大きさを測りました。同じクラスタで同じ流れを旧コレクタと 新コレクタでそれぞれ走らせました。

横にスクロールすると残りが見えます

同じ流れを二つのコレクタで測った投入時刻ごとの遅延。
行 (投入時刻)旧コレクタ新コレクタ
一つ目 (t=0秒)4.846秒0.524秒
二つ目 (t=2秒)3.928秒0.517秒
三つ目 (t=44秒)0.936秒0.943秒

三つ目の行が自然な対照群です。t=44秒に投入された行なら旧コレクタの監視も すでに付いていたので変わらないはずで、実際に0.936秒と0.943秒で同じでした。だから前の二行で 縮んだ4.3秒と3.4秒はシステムが速くなったのではなく測定誤差でした。

出口だけを守り入口は誰も守っていませんでした#

片付けの手順は、実行が終わるときに残りがないことを証明します。ところが始まるときを見る側は 誰もいませんでした。

ラベルと taint はこれからの配置を止めるだけで、すでにあるものを追い出しません。 前の実行の片付けが詰まって残った終了中の Pod は依然としてデバイスを握っているのに、taint からは 見えません。そこで Worker を確保した直後で最初の生成より前の位置に検査を入れました。容量と外来の 消費者とノードの状態を見て、その観測をレコードに残します。

容量の要求値はフィクスチャから導きます。ハードコードするとフィクスチャが変わったときに検査が 静かにずれます。最初は割り当ての合計だけを見ていましたが、レビューが最大の単一要求も 境界だと指摘しました。ジョブはノード一つにまるごと入るので、総量がいくら潤沢でも3枚の 要求は2枚のノードでは回りません。二つの境界の最大値を取り、どちらが縛ったかを名前で残すように 直しました。

二つの時点だけを見ると真ん中が空きます#

排他性は確保と解放の二つの時点でしか検査されていませんでした。第三者がそのあいだに taint を 外し、別の作業を入れ、解放の前に戻せば二つの検査は両方とも通ります。それでも測定された日程は 汚染されています。

実際に実行の途中で taint を外し、元の値のまま戻してみました。解放時点の検査は 正常に通り、連続した観測だけが違反1件を捕まえました。四つの Node 版にわたって設置された値が 分かれたという記録が残り、実行は無効になりました。

証拠の側にも一箇所空きがありました。入口と持続は自分の証拠をレコードに残すのに、観測の連続性の 証拠だけが残りませんでした。ストリームごとの基準点と確立の時刻と終了の理由がなければ、保存された レコードを持つ監査者は完全な観測と切れた観測を区別できません。そこで判定を自由な文ではなく フィールドから導きました。文を読む判定は理由が一つに覆われると見落とし、 証拠から導く判定は見落としません。

対比そのものを資格にしました#

この実験が測るのは回収です。一方は終了信号を尊重する作業で、もう一方は無視する作業で、 違いはシェルのコマンド一行です。クラスタが信号をきちんと届けられないと二つの側は一つに潰れるのに、 数字は正常に見えます。

# 尊重する側: 信号を受けたらその場で出ます
sh -c "trap 'exit 143' TERM; sleep D & wait"

# 無視する側: 同じ信号を受けても猶予が切れるまで残ります
sh -c "sleep D"

# 資格の判定。二行が違う終わり方をしてはじめてこのクラスタで対比が成り立ちます
#   尊重  1024ms  exit 143 (TERM)
#   無視 31138ms  exit 137 (KILL)

要点は対比そのものを資格にしたことです。尊重する側が早く出ることだけを見ると、すべてを即座に 強制終了するランタイムが間違った理由で通ります。無視する側が猶予の締切まで 耐えることも一緒に見る必要があります。

そしてこれを毎回の儀式ではなく組み合わせごとに一度としました。イメージとクラスタとランタイムと Harness が同じなら同じ答えが出るからです。

横にスクロールすると残りが見えます

終了カナリアが資格の鍵に入れるもの。
鍵に入れるものなぜ入れるか
イメージのダイジェストイメージが変われば信号の伝わり方も変わりえます
両方のレンダされたコマンド対比を作るのがこの二行です
猶予時間実行時間の算術四箇所がこの値を前提にしています
Node UID · kubelet 版 · コンテナランタイム信号を実際に届けるのはこちらです

保存先は Node の注釈です。資格の対象の多くがそのノードの性質で、権限も すでにあり、ノードと一緒に消えます。

同じ形が九回出てきました#

この作業で一番価値のある成果物はコードではなく欠陥の分類でした。同じ形が繰り返し出てきました。

横にスクロールすると残りが見えます

一つの作業で繰り返した九つの欠陥の形。
形実際の例
呼び出し元のないコンポーネントレビューもコミットも経たのに実行経路で呼ぶ箇所がゼロ
自分自身と比べる表明出力を同じ定数と比べるので綴りを変えると両辺が一緒に変わります
自分で名付けた欠陥に通る罠テスト900ミリ秒しか観測しないのに注入した遅延は15秒
空虚な表明解放が注釈を消すので最終状態だけ見るとガードの有無と無関係に通ります
記憶で断言した否定「そんなレコードは一時フォルダの外にない」に自分の実行が反例
主経路にない性質を主張するコメント「窓を片付けのあいだ開けておく」が地平線に届く全実行で偽
直しながら同じ種類を作る修正種別ごとのマップに変えて種別ごとに最後の項目だけ読むようになりました
別々の理由で無力になった二つのガードの重なり重なった箇所だけが無防備

最後の行が一番よく出ました。偽クライアントが五回現実を隠し、そのうち一つは 条件付き削除を無視したせいでそのガードが一度も実行されたことがありませんでした。

限界: この記事が主張しないこと#

  • ⚠️ ゲートを立てたことと、この道具を信頼できることは別です。ゲートは自分が見る範囲の中でしか 語りません。
  • 表の遅延の値は一つのクラスタで一度ずつ測った値です。繰り返していないので分布ではありません。
  • 終了カナリアは自分で作った作業を調べます。実験の作業が通る別の経路はそれでは行使されず、 レコードがその事実を自分で書きます。
  • 九つの形はこの作業から出たもので、一般的な頻度の順位ではありません。
  • これらの実行は kind クラスタと偽のデバイスプラグインの上で回りました。実デバイスではありません。

おわりに#

この記事の結論は一行です。ガードを読んで検証しても、そのガードが実際に何を捕まえるかは 分かりません。権限を一つの動詞だけ削り、ファイルに欠陥を入れて拒否を実際に発火させたら、 ガード自身の穴が出てきました。

そして道具を直したあとは、直した効果の大きさを測る必要があります。一つの実行の中に動かないはずの 行を置けば、その行が対照群になってくれます。

②編は、そうして直した道具で比較を初めて回した話です。
