상품 검색 02. 학습 질의 53,882개의 ID에 정답 상품 ID를 넣었습니다

사진 속 옷과 같은 상품을 찾는 검색을 만들고 있습니다. 질의 사진마다 ID를 붙였는데 그 ID 안에 정답 상품 ID를 그대로 넣었습니다. 학습셋 질의 53,882개 전부였습니다.

실험을 돌리기 전, 실험 계약을 검토하는 단계에서 이 문제를 찾았습니다. 이 글에서는 ID 형식을 고친 이유와 방법, 남은 한계를 설명합니다.

옛 ID로 돌린 학습·판정 실험은 없습니다. 정답이 실제로 샌 결과는 없습니다. 샐 수 있던 경로를 실험 전에 막은 이야기입니다.

이 글의 예상 독자#

  • 평가 데이터의 정답을 학습 쪽에 새지 않게 관리해야 하는 분
  • 사람이 읽기 쉬운 ID를 만들어 쓰고 있는 분
  • 모의 사용자(시뮬레이터)로 피드백 데이터를 만드는 분

ID에 정답 상품 ID가 들어 있었습니다#

처음 형식은 출처:상품ID:이미지 Hash 앞 12자였습니다. 로그나 순위 파일을 열면 어느 상품의 질의인지 바로 알 수 있어 디버깅할 때 썼습니다. 그런데 그 상품 ID가 바로 그 질의의 정답이었습니다.

무엇이 위험했을까#

이 프로젝트에서는 시뮬레이터가 정답을 보고 "맞다" 또는 "아니다"를 답합니다. 이 모의 교정으로 얻은 라벨로 재정렬 모델을 학습합니다. 정답은 시뮬레이터와 평가 코드만 읽어야 합니다.

그런데 순위 파일, 교정 이벤트, 라벨에 모두 질의 ID가 들어갑니다. 어떤 후보에 라벨을 붙일지 고르는 선택기도 질의 ID를 받습니다.

ID에 정답이 들어 있으면 정답을 읽지 않도록 설계한 코드도 문자열을 나누기만 하면 정답을 얻습니다. 예를 들어 후보 상품 ID가 질의 ID에 들어 있는지 확인하는 특징을 넣으면 모델이 ID에서 정답을 읽을 수 있습니다. 이 모델의 학습 곡선으로는 검색 모델의 학습 효과를 판단할 수 없습니다.

계약 검토에서 찾았습니다#

라벨 선택 계약(c4)을 확정하기 전에 다른 모델에게 이 계약을 반대 입장에서 검토해 달라고 요청했습니다. 지적 중 하나([A10])는 ID 형식이 「정답 대응은 시뮬레이터와 평가만 읽는다」는 계약을 어긴다는 것이었습니다.

학습셋 질의 53,882개를 확인해 보니 100%가 질의 ID 안에 정답 상품 ID를 그대로 갖고 있었습니다.

두 Commit으로 고쳤습니다#

가로로 넘겨 표 전체를 볼 수 있습니다.
Commit바꾼 것
071505e질의 ID를 출처:sha256(출처, 상품ID, 이미지 Hash)의 앞 16자로 바꿨습니다. 같은 질의는 늘 같은 ID를 얻습니다. ID 문자열에 상품 ID를 그대로 넣지 않습니다
adf658a시뮬레이터가 순위 파일을 읽을 때 :로 나눈 질의 ID 조각 중 정답 상품 ID와 같은 것이 있으면 실행을 거부합니다. 옛 형식의 순위 파일이 다시 들어오는 것을 막습니다

ID를 바꾸면 라벨 선택 결과도 달라집니다. 라벨 선택 정책은 질의 ID 순서로 질의를 정렬한 뒤 난수로 고릅니다. ID가 바뀌면 같은 seed로도 고르는 질의가 달라집니다.

그래서 순위 파일을 새 ID로 다시 만들었습니다. 사전등록 실험에서 쓸 파일도 이 새 파일로 고정했습니다. 실험 결과를 보기 전에 바꿨으므로 결과를 보고 파일을 고르지는 않았습니다.

남은 한계#

새 ID도 공개된 공식으로 만든 값입니다. 이미지 Hash와 후보 상품 ID를 아는 코드라면 후보마다 같은 공식으로 Hash를 계산해 질의 ID와 맞춰 볼 수 있습니다. 비밀 키를 섞은 Hash로 바꾸면 이 비교를 막을 수 있습니다. 다만 ID를 바꾸면 선택 순서도 다시 바뀝니다.

이번에는 ID를 더 바꾸지 않고 선택기와 학습기가 받을 수 있는 입력을 정해 두었습니다. 입력은 순위 파일의 질의 ID, 후보 목록, 점수, 후보 통계, 임베딩 벡터, 라벨입니다. 정답 필드를 바꿔도 학습 결과와 재정렬 순서가 바뀌지 않는지 테스트로 확인합니다. 이 한계는 학습 곡선 계약(§8)에 그대로 적었습니다.

이 글이 주장하지 않는 것#

  • 실제로 정답이 샌 실험이 있었다는 것. 옛 ID로 돌린 학습·판정 실험은 없습니다. 실험 전에 고쳤습니다.
  • 새 ID가 완전히 안전하다는 것. 공식이 공개돼 있어서 입력 제한과 테스트로 막고 있습니다.
  • 다른 데이터의 ID도 안전하다는 것. 이 확인은 LRVS 학습셋 질의에 대한 것입니다.

마치며#

디버깅하기 쉽게 만든 질의 ID에 정답 상품 ID가 들어 있었습니다. 학습셋 질의 53,882개 전부였습니다. 실험 전 계약 검토에서 찾았습니다.

ID에서 상품 ID를 뺐습니다. 옛 형식이 다시 들어오면 실행을 거부하게 했습니다. 공식이 공개된 한계는 입력 제한과 테스트로 막고 있습니다.
