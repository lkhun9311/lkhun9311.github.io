Connection Pooler: connection pooler란?

데이터베이스 · #Connection Pooler

목차

  • 왜 필요한가
  • connection pool과 다른 것이다
  • 무엇을 못 고치나
  • 이 사이트에서 쓰인 곳
  • 함께 볼 용어

애플리케이션이 여는 connection 수천 개를 DB connection 수십 개로 묶어 주는 중간 서버입니다. RDS Proxy · PgBouncer · Supavisor 같은 것들입니다.

왜 필요한가#

PostgreSQL은 connection 하나마다 backend 프로세스를 하나씩 만듭니다. 그 프로세스는 아무 일도 안 하고 있어도 메모리를 씁니다. 그래서 앱 인스턴스를 늘릴수록 DB 쪽이 먼저 한계에 부딪힙니다.

앱 인스턴스 100대 × pool 크기 20 = connection 2,000개
그런데 실제로 지금 쿼리를 실행 중인 건 50개
나머지 1,950개는 그냥 열려만 있다

connection pooler는 이 2,000개를 받아서 실제로 일이 있는 것만 뒤쪽 connection 50개에 얹습니다. 열려만 있는 connection의 비용을 없애 주는 것입니다.

connection pool과 다른 것이다#

이름이 비슷해서 자주 헷갈립니다.

  • connection pool(HikariCP 등) — 앱 안에 있습니다. 앱이 DB connection을 재사용하려고 들고 있는 목록입니다.
  • connection pooler(RDS Proxy 등) — 앱과 DB 사이에 있는 별도 서버입니다. 여러 앱의 connection을 합칩니다.

즉 pool은 "한 앱이 자기 connection을 아끼는 것", 풀러는 "여러 앱의 connection을 DB 앞에서 합치는 것"입니다.

무엇을 못 고치나#

connection 부족에는 원인이 두 가지 있고, 풀러는 하나만 고칩니다.

  • connection 개수가 많아서 — 풀러가 정확히 이걸 위한 도구입니다.
  • connection을 오래 붙잡고 있어서 — 풀러가 구조적으로 못 고칩니다.

이유는 transaction pooling의 정의에 있습니다. connection 재사용은 transaction과 transaction 사이에서만 일어나는데, transaction이 열려 있는 동안에는 그 connection이 한 클라이언트에 묶이기 때문입니다. transaction이 10초 열려 있으면 뒤쪽 connection도 10초 묶입니다.

이 사이트에서 쓰인 곳#

  • RDS Proxy 로는 못 고치는 connection 고갈

함께 볼 용어#

  • transaction pooling — 풀러가 connection을 재사용하는 방식
  • connection pool — 앱 안쪽의 그것
