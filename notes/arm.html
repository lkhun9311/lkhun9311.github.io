Arm
One branch of a comparison run. One variable differs; everything else is held the same.

The name for one branch of a comparison run. The word comes from clinical trials: arm A and arm B must differ in one thing and match in everything else.

Why this word#

In a clinical trial each branch of the patient groups is called an arm (the treatment arm, the placebo arm). A performance measurement has the same shape: hold the conditions, change one thing, compare the results.

Change one variable#

Break this and you cannot say what the result came from. An error I actually made: I compared two runs where one was cache 5s + sequential and the other no cache + parallel. I wrote the difference up as "thanks to the parallelism", but two variables were confounded.

So when an arm changes, pool size, thread count, external latency and the data are all held fixed.

Keep a code difference in a patch#

When the arm is a code difference, keep that difference in one patch file and apply and revert it per run. Edit by hand and one day you forget to revert, and every result from that run is void.

perf/arms/inside-transaction.patch      arm B — restores @Transactional
perf/arms/sequential-classifiers.patch  arm SEQ — puts the classifiers back in sequence

The runner reverts automatically on exit, including when the run fails part way.
