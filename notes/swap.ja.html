Swap

性能測定 · #Warm-up

Swap は RAM が足りないときにページをディスクへ退避させる場所です。 降りれば Swap Out、また必要になって上がれば Swap In です。プロセスはその間を知りません。 読み取り 1 件のコストだけが静かに変わります。

RAM が増えたわけではありません#

Swap はメモリを増やす仕掛けに見えますが、増えたのはアドレス空間であって速度ではありません。 RAM で終わったはずの読み取りがディスクの往復になるので、同じ問い合わせがそのままで遅くなります。 桁で言えば RAM は 0.0001ms 側、Swap は 10ms 側です。

つまり Swap のある機器の性能は、問い合わせやコードではなくページが今どこにあるかで決まります。 上の層をいくら覗いても理由の出てこない種類の遅さは、ここから来ます。

埋まっているのは状況で、原因ではありません#

free -h が Swap 8.0Gi 8.0Gi を見せれば目立ちます。しかしそれは いつか降りたページがまだそこにあるという話です。ずっと前に降りて誰も探さない ページで埋まっていても、数字は同じ 8.0GiB です。

今遅い理由が Swap だと言うには行き来する量を測る必要があります。 vmstat の si・so が毎秒何 KiB か、当のプロセスに major page fault が毎秒何件出るかです。この二つが無ければ残るのは 「埋まっていた」と「空けたら速くなった」の二つの事実で、その間は推測です。

切る命令は戻す手順を先に書きます#

swapoff -a は Swap にあったものをすべて RAM へ引き上げます。 その分の空きが無ければ命令が失敗するか、カーネルがメモリを回収しようとプロセスを殺します(OOM killer)。 先に見るのは free -h の available で、この値が Swap の used より大きい必要があります。

swapoff -a && swapon -a にはもう一つ罠があります。装置が複数あると一部だけ切れたまま swapoff が 0 以外で終わることがあり、&& は前が 0 のときだけ後ろを実行します。 半端に失敗すると Swap が切れたまま残ります。戻す手順を先に書いてから触る命令です。
