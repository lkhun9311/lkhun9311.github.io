SSE

性能測定 · #Warm-up

SSE(Server-Sent Events)は接続を一度張っておき、サーバーが値を押し込む方式です。 ブラウザが尋ねるたびに答えるリクエスト・レスポンスとは逆です。

何か#

普通の HTTP は尋ねれば答えて切ります。次の値が必要ならまた尋ねます。だから画面が最新を保つには 数秒ごとに呼び直すことになり、その周期がそのまま古さの上限になります。

SSE は接続を開けたままにします。サーバーは値を作るたびにその接続へ書き込みます。ブラウザ側は 標準の API 一つで受け取ります。WebSocket と違って一方向なので、ブラウザから 送るものが無ければそちらが安く済みます。

接続が開いたことと値が来たことは違います#

この区別がこのサイトのいくつかの記事で問題になりました。接続自体はすぐ張られます。ところが 最初の値が来るまでにはサーバーがその値を作らなければなりません。そのあいだ画面は空です。

応答時間を測るときに接続が張られた時刻を測ると、いつも速く出ます。利用者が待ったのは最初の値で、 その二つは数秒ずれることがあります。

遅い一人が全体を塞ぎます#

接続が開いているので書き込みが塞がることがあります。ネットワークの遅い クライアントが一つ受け取らなければ、そちらへの書き込みが止まります。その状態で配信するコードが Lock を握っていると、ほかの接続も一緒に止まります。

そこで値を作る仕事と送る仕事を分けます。作る側は Lock の中で終え、送る側は Lock の外でそれぞれ回します。

このサイトで使われている記事#

  • REST と SSE の片方だけ直しても画面はそのままでした
  • 直す根拠が見つからないと書いた画面が 6.8 秒でした
