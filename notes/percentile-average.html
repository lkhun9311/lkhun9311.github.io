Why not the average

Performance measurement · #Percentile

Contents

  • In numbers
  • It is wrong in both directions
  • When an average is the right tool

← Percentile overview

An average is not a value that existed. It is everything added and divided, so when a fast group and a slow group are mixed it points somewhere between them, whether or not any request is there.

In numbers#

Take 99 requests at 10ms and one at 10s. The average is about 110ms, and not one request came anywhere near it. The fast side is 10ms and the slow side is 10s.

It is wrong in both directions#

Read only the average and a fast screen looks slow. 99 requests took 10ms and the report says 110ms. There is nothing to fix and someone goes to fix it.

At the same time the slow one hides. Add a second 10s request and the average becomes 210ms, which reads as “twice as bad”, not as “there are two ten-second requests”.

When an average is the right tool#

This is not an argument to drop averages. For totals the average is correct. “How much CPU does this API use in a day” is the average times the call count; no percentile gives you that.

The line is this: percentiles for what a person waits on, averages for what a resource consumes.
