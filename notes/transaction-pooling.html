Transaction Pooling: 트랜잭션 풀링이란?

데이터베이스 · #Transaction Pooling

목차

  • 세 가지 모드
  • 핵심 성질 — 언제 묶이나
  • 핀(pin)이 걸리는 패턴
  • 이 사이트에서 쓰인 곳
  • 함께 볼 용어

커넥션 풀러가 뒤쪽 커넥션을 재사용하는 방식 중 하나로, 트랜잭션 단위로 빌려주고 돌려받습니다. 트랜잭션이 끝나야 그 커넥션이 다음 클라이언트에게 갑니다.

세 가지 모드#

PgBouncer 기준으로 세 가지가 있습니다. 뒤로 갈수록 재사용이 잘 되지만 쓸 수 있는 기능이 줄어듭니다.

  • 세션 풀링 — 클라이언트가 연결을 끊을 때까지 커넥션을 붙들고 있습니다. 재사용이 거의 없습니다.
  • 트랜잭션 풀링 — 트랜잭션 단위. 실무에서 가장 많이 쓰는 모드입니다.
  • 스테이트먼트 풀링 — 쿼리 하나 단위. 트랜잭션을 쓸 수 없습니다.

핵심 성질 — 언제 묶이나#

이 한 줄이 전부입니다.

커넥션 재사용은 트랜잭션과 트랜잭션 사이에서만 일어난다. 트랜잭션이 열려 있는 동안에는 그 커넥션이 그 클라이언트에 묶인다(pin).

당연한 이야기입니다. 트랜잭션은 상태이고, 열려 있는 중간에 다른 세션에 빌려주면 격리가 깨집니다.

그래서 이렇게 됩니다.

트랜잭션이 10초 열려 있음
  → 뒤쪽 커넥션도 10초 묶임
  → 앱 커넥션 1개당 DB 커넥션 1개
  → 풀러가 줄여 주는 게 없음

즉 짧은 트랜잭션이 많을 때 값을 하는 도구입니다. 트랜잭션 안에서 외부 API 를 기다리는 코드에는 효과가 없습니다.

핀(pin)이 걸리는 패턴#

아래 패턴이 코드에 있으면 트랜잭션이 끝나도 커넥션이 계속 묶여, 풀러가 무력해집니다.

  • 세션 스코프 advisory lock (pg_advisory_lock) — pg_advisory_xact_lock 은 괜찮습니다(트랜잭션 종료 시 해제)
  • 임시 테이블
  • SET · set search_path
  • 서버 프리페어드 스테이트먼트 (풀러와 버전에 따라 다름)

그래서 풀러를 도입하기 전에 이 넷이 코드에 있는지 먼저 확인해야 합니다. 도입한 뒤에 알면 돈은 이미 나갔고 효과는 없습니다.
