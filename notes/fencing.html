Fencing

Performance measurement · #Warm-up

Contents

  • Why it is needed
  • How it is done
  • No path means no recovery
  • Where it is used on this site

Fencing is making sure the original is off before recovery starts. If that cannot be confirmed, recovery does not run.

Why it is needed#

A node that stops answering looks dead. But not answering means I cannot see it, not it has stopped. A switch may have failed while the node kept running.

Start the same VM elsewhere in that state and the original and the copy write to one volume at once. No filesystem assumes that, so the data breaks. This is the case where automatic recovery costs more than the failure did.

How it is done#

Asking the node to stop itself does not work; being unable to ask is what created the situation. Fencing goes through a path outside the node.

  • Power · cut it through the BMC or IPMI. Certain, as long as that path is alive.
  • Storage · revoke the node's access to the volume. It keeps running but cannot write.
  • Network · shut the port at the switch, though sessions already open may survive.

No path means no recovery#

If the fencing path itself is down, the original cannot be turned off, and nothing may be started. The right answer then is to do nothing and call a person. Not giving up on automatic recovery, but setting the default to stop when certainty is missing.
