SSE

Performance measurement · #Warm-up

Contents

  • An open connection is not an arrived value
  • One slow consumer blocks the rest
  • Where it is used on this site

SSE (Server-Sent Events) holds one connection open and lets the server push values into it. The opposite of request and response, where the browser has to ask each time.

What it is#

Ordinary HTTP answers and closes. Needing the next value means asking again, so a screen that wants to stay current re-fetches every few seconds, and that interval becomes the ceiling on how stale it can be.

SSE leaves the connection open and the server writes into it as values appear. The browser takes them through one standard API. Unlike a WebSocket it is one-way, which is cheaper when the browser has nothing to send back.

An open connection is not an arrived value#

That distinction caused trouble in several articles here. The connection itself opens immediately. The first value still has to be produced. Until it is, the screen is empty.

Measure response time at the moment the connection opens and it always looks fast. What the user waited on is the first value, and the two can be seconds apart.

One slow consumer blocks the rest#

Because the connection stays open, a write can block. One client on a slow network that stops reading stalls the write to it. If the code broadcasting holds a lock while that happens, every other connection stalls with it.

So producing a value and sending it are kept apart: produce inside the lock, send outside it.
