Timeout は待つことに掛ける上限です。 上限なので、二つのことを意味しません。実際にそれだけ掛かったという意味でも、そこまでは安全だという意味でもありません。

Connect と Read は別の区間を切ります#

Connection Timeout は接続を確立するのにかかる時間を、Read Timeout は 送ってから応答を待つ時間を切ります。相手が接続だけすぐ受けて応答を返さなければ、 Connection Timeout は何もしません。

どちらも無ければ要求は上限無しに待ちます。そして Timeout が消えても正常な応答は正常に来ます。 設定をまるごと差し替える途中で自動設定が付けていた Timeout を一緒に飛ばしても、普段は何の症状も出ません。 症状は相手が遅くなる日にだけ出ます。

設定値は測定値ではありません#

「この呼び出しは最大 10s」という文は、たいてい設定ファイルから読んだものです。要求ごとにそれだけ 掴んでいたと観測した値ではありません。同じ呼び出しの実測 p95 が 5ms 対 8ms のこともあります。

容量の計算ではこの差が倍数で開きます。上限を占有時間として入れると、資源が実際の数百倍に見積もられます。 測っていない値は測っていないと書き、計算には測った値を入れます。

上限に貼り付いた値は遅延ではありません#

負荷テストのレポートに P99 が 600,017ms と出ていれば、それは 10min の上限に貼り付いた値です。 その要求は終わっていません。終わらなかった要求の遅延は「600s」ではなく、分からないが正解です。

この欄を P99 として引用すれば、測れなかったものを測ったふりをすることになります。エラー率 83.3% の構成の パーセンタイルは残った 16.7% についてのものであり、全体についてのものではありません。表には残し、読み方を併記します。
