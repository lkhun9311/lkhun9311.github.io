There are two ways to compute it

← Percentile overview

The same data gives different p99s in different tools. Not because the arithmetic is wrong, but because there are two ways to settle what “the 99% position” means.

There is no 19.8th value#

With 20 samples the 95% position falls between the 19th and the 20th, at the 19.8th. No such value is in the line. This is where the two paths separate.

Nearest rank#

Round the position up and use the 20th value. It is a value that is actually in the line, so “a request produced this value” stays literally true. JMeter works this way.

The cost is that small samples move in steps. Going from 20 samples to 21 makes the same position point at a different value.

Linear interpolation#

Compute proportionally between the 19th and 20th values. The number moves smoothly as samples accumulate. Prometheus's histogram_quantile is in this family.

The cost is that the result may not be in the line. “p95 is 187ms” can be true while no request took 187ms.

What to do about it#

  • Before putting two tools' p99s side by side, check that both use the same method.
  • The gap widens on small samples. On a 20 to 30 sample comparison, “p99 changed” may be the method, not the system.
  • When a percentile goes in a report, put the sample count next to it. Without it there is no way to know how much that number moves.
